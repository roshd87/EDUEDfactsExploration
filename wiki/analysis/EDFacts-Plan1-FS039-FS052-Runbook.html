EDFacts from Ed-Fi and the EDU warehouse

Producing FS039 Grades Offered and FS052 Membership

The order of work for the two files that core Ed-Fi covers completely: the manual inputs an SEA settles before any SQL runs, the precursor EDPass submissions that must exist before either file is accepted, the warehouse and edu_ext_edfacts build, and the upload. A closing table grades each data element against the current edu_wh and edu_edfi_source models.

A. Pre-steps, once per school year

nothing here is in the ODS
1
manualFreeze the federal specs

ed.gov blocks every non-browser client, so a person runs the Chrome-driven fetch, then the freeze script, and regenerates the four spec seeds. Repeat when the files go Active or a revision posts.

→ edfacts_category_sets edfacts_layouts edfacts_permitted_values edfacts_files
2
manualAnswer the three FS5017 policy questions

Does the state offer ungraded instruction, Grade 13, Adult Education? These answers drive which grade rows exist in both files and are typed again into EDPass later.

→ edfacts_config (today: the exclude_values argument)
3
manualSet the membership count date

October 1, or the closest school day when Oct 1 is not one. The same date decides which units are operational for FS039 and FS052.

→ edfacts_config.member_date
4
manualSet the file identity values

FIPS state code, USPS abbreviation, state agency number (01), the seven-character submission id and the free-text file identifier that go in every header.

→ dbt vars edfacts_state_code edfacts_state_abbr edfacts_submission_id
5
manualReview the descriptor crosswalks

Pre-filled from the Ed-Fi 6.1 default descriptors, which already carry the EDFacts vocabulary for most of these. A state with custom descriptors confirms each mapping:

  • grade level → PK KG 01…12 13 UG AE; decide Preschool, Early Education and Transitional Kindergarten
  • sex → M F; decide what Non-binary and Not Selected become (MISSING is the only other permitted value)
  • race descriptors + Hispanic flag → AM7 AS7 BL7 HI7 PI7 WH7 MU7
  • school type → DG21 1–5; the default set includes "Reportable Program"
  • operational status → DG16/DG531 1–8; the default set has the same eight values (Active = Open)
  • LEA category → DG453 1–9; charter status → DG27 YES/NO and DG653
→ xwalk_edfacts_* seeds
6
manualCollect the directory facts Ed-Fi does not hold

Three FS029 fields have no core Ed-Fi source and are supplied by hand, usually as a small seed keyed by state school id:

  • charter authorizer ids (primary, secondary) for every school with charter status YES, and the FS190 roster those ids point at
  • reconstituted status (DG743), defaulting to NO
  • operational status changes after the start of the year, with their effective dates
→ edfacts_directory_overrides seed

B. Precursor EDPass submissions

the directory must be complete before any other file is accepted
7
edpassSEA directory

Rolled over from the prior year by EDPass. No file, no action. Confirm the SEA record is present before uploading anything.

8
ed-fiRead the LEA and school records

Names, websites, categories, operational and charter status from the two dims; mailing addresses, NCES identification codes and institution telephones from the staging layer beneath them.

dim_lea dim_school stg_ef3__*__addresses stg_ef3__*__identification_codes
9
buildFS029 LEA directory
  • one row per LEA the tenant owns (is_owning_lea), status through the operational xwalk
  • NCES id from the identification codes where the system is NCES; blank is allowed only for New, Future and Added
  • mailing address from the Mailing row, location from Physical; out-of-state flag when the address state differs
  • telephone needs a one-line flatten of v_institution_telephones, which no staging model does today
→ ssLEADIRECTORYvvvvvvv.txt (1005-char records)
10
edpassUpload the LEA directory

Supervisory unions in a first transmittal, subordinate LEAs in a second, if the state has them. An LEA record must exist before any school under it is accepted.

11
manualFS190 charter authorizer roster

Only when any school has charter status YES. Core Ed-Fi has no authorizer organization, so this file is assembled by hand from the overrides seed and uploaded before the school directory, which references its ids.

12
buildFS029 school directory
  • one row per school, same address, id and telephone handling as the LEA file
  • school type through the xwalk; charter status YES unless the descriptor is "Not a Charter School"
  • authorizer ids and reconstituted status joined from the overrides seed
→ ssSCHDIRECTORYvvvvvvv.txt (1081-char records)
13
edpassUpload the school directory, then confirm

After processing, download the Directory and Grades Offered report from EDPass and check that every unit the build will report in FS039 and FS052 is present and operational. Fix directory rejections before going on.

C. FS039 Grades Offered

build before FS052; Membership is defined against it
14
ed-fiRead the school grade spans

The school resource's grade level collection, staged one row per school per grade, plus school type and operational status from the dim and the LEA each school belongs to.

stg_ef3__schools__grade_levels dim_school dim_lea
15
buildGrades offered population
  • the unit list from step 12: operational on the count date, not a reportable program
  • map each grade through the xwalk; drop UG / 13 / AE rows the state said it does not use
  • LEA rows = the union of its schools' grades; an LEA with none gets one NOGRADES row
→ one row per unit per grade
16
buildWrite and test the FS039 files

edfacts_file emits the header and 283-character fixed-width records. Spec tests check codes and record lengths; the FS039 BRSI rules run as brsi_* tests.

→ ssLEAGRADESOFFvvvvvvv.txt ssSCHGRADESOFFvvvvvvv.txt
17
edpassUpload FS039, enter FS5017

Upload the LEA file then the school file. Type the three FS5017 answers from step 2 into the CCD Grades Offered metadata page. Since SY 2025-26 they are submitted separately, not as a package.

D. FS052 Membership

headcount on the count date, one school per student
18
ed-fiRead enrollment and demographics

Enrollment spans with entry grade and the LEA key, and the student's sex, race/ethnicity and Hispanic flag. All Direct in core Ed-Fi; nothing is derived except the as-of filter.

fct_student_school_association dim_student
19
buildMembership population on the count date
  • in membership when entry date ≤ count date and exit date is null or after it (exit-date inclusivity follows the warehouse var)
  • one school per student: is_primary_school, then latest entry on a tie
  • grade from the counted enrollment's entry_grade_level, not the student-year grade on dim_student
  • units from step 12 minus any reporting NOGRADES; students outside the unit's grade span go to subtotals 1 and 4 and the total only
20
buildedfacts_counts

One GROUP BY per set, unioned: Category Set A (grade × sex × race, indicator N), subtotals 1–4, and the education unit total (indicator Y). Zero-fill only the grades the unit reported in FS039; a unit with no students gets a zero total and no detail rows.

21
buildWrite and test the FS052 files

Header plus 325-character records for SEA, LEA and school. Tests: edfacts_conforms, edfacts_sets_sum_to_total, edfacts_record_lengths, the FS052 BRSI rules, and the cross-file check that every FS039 grade has an FS052 count.

→ ssSEAMEMBERvvvvvvv.txt ssLEAMEMBERvvvvvvv.txt ssSCHMEMBERvvvvvvv.txt
22
manualWrite the FS5024 narrative answers

Can the state tell grades offered from grades enrolled at school and district level; what the PK count includes (Head Start, IDEA preschool, state pre-K); why school, LEA and SEA totals differ if they do. Free text, 4,000 characters each.

23
edpassEnter FS5024, upload FS052, submit the package

Type the FS5024 answers, upload the three FS052 files, and submit once both show Ready to Submit. Membership and its metadata go as one data package. Processing takes 45 to 60 minutes; resolve any BRSI errors and attach data notes, then resubmit.

What the evaluation says

FS039 and FS052 are build-ready

Every element has a column. The work is five crosswalk seeds, the FS039 grade gate in the FS052 macro, and the −1 rule. Nothing has to change in edu_wh for the two target files.

The precursor is where the manual work sits

FS029 needs one new staging flatten (institution telephones) and an overrides seed for the five fields core Ed-Fi lacks: authorizer ids, reconstituted status, dated status changes, prior ids. All four files share the same unit list, so build the directory population once and reuse it.

Two warehouse behaviours to know

Org staging dedupes to the latest API year, so a rerun for a past year reports today's operational status. And dim_student is one row per student-year with the latest grade, so Membership must take grade from the enrollment it counts.
