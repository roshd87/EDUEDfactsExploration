EDFacts Files from Ed-Fi and EDU: Work Outline

Baseline SY 2026-27 · Pre-planning, as of 2026-10-13

Objective

  • Make EDFacts files that EDPass accepts.
  • Use the EDU warehouse as the only data source at run time. The warehouse holds Ed-Fi ODS data.
  • Ship the work as one dbt extension package, edu_ext_edfacts. Any Stadium partner can install it.
  • Read CEDS Generate for business rules only. Do not run Generate.

Sources of truth

  • The EDFacts file specifications for SY 2026-27 give the file content. The repo keeps a checksummed copy.
  • The EDFacts Workbook, the Business Rules Single Inventory (BRSI), and the EDPass metadata guides give the edit checks.
  • Ed-Fi Data Standard 6.1.0 gives the source schema and the initial descriptor values only.
  • Each Stadium and Ed-Fi implementation has state-specific descriptors. Do not assume a static descriptor set. Read the descriptors from each state implementation.
  • The dbt docs for each Stadium deployment give the model map for that state. Some states have state-specific models that hold EDFacts data. Read the dbt docs for each state.

Background investigation complete

  • No build work has started. The items below are investigation results that the plan uses.
  • The SY 2026-27 catalog is frozen: 94 specifications and 43 companion documents, with a manifest.
  • SY 2025-26 and SY 2026-27 are compared. No record layout changed. Eleven specifications changed guidance.
  • A read of all Generate SQL found 336 rules the specifications do not state. The Generate wiki keeps the domain notes. A rule-by-rule register is not kept.
  • A field review of all 94 specifications is complete. 88 fields are shared between files.
  • The seed builder makes four seed families from the specifications: category sets, layouts, permitted values, and file headers.
  • The count macro makes GROUPING SETS queries from the category-set seed. It adds Total Indicator rows and zero rows.
  • The file macro makes the header and the fixed-width records.
  • FS052 Membership renders from seeds alone, as a proof of shape. The fixture build passes 21 of 21 tests.

Phase 1: build the seeds and macros

  • Add each specification to the seed builder allowlist, one at a time. Correct the builder when its asserts show a new shape.
  • Make the edfacts_config seed. Give it one column for each SEA policy answer in the FS5002 to FS5029 metadata collections.
  • Make the xwalk_edfacts_* seeds. Start from the Ed-Fi 6.1 default descriptors. Add each state's own descriptors from its implementation. Review the map with the state.
  • Add the missing-count value of -1 to the count macro.
  • Add the BRSI edit checks that SQL can express as dbt tests.
  • Optional: rebuild the Generate rule register. Do fieldwork with the first state to assess the need. Rebuild the register only if the specifications and the Generate wiki do not answer the open rules.

Phase 2: build three vertical slices

  • Read the dbt docs for the target state first. Find the models that hold each EDFacts input.
  • Build the Membership slice: FS052 and FS039. Use the student school association on the count date.
  • Build the IDEA Child Count slice: FS002 and FS089. Use special education program eligibility on the count date.
  • Build the Directory slice: FS029 at SEA, LEA, and school level. Use organization attributes and status changes.
  • Run each slice on the Grand Bend sample ODS. No partner data is necessary.
  • Make sure each file passes every BRSI check that SQL can express. Make sure each record length agrees with the layout seed.

Phase 3: roll out by collection

  • Ship one wave for each collection group, in this order: CCD organization, IDEA student, staff, program participation, outcomes, assessment, finance.
  • Apply the SY 2026-27 guidance changes to FS118, FS195, FS113, FS125, FS127, and the assessment files.
  • Get staff qualification data from a side door before you build the staff wave. Ed-Fi core does not hold it.
  • Get finance amounts and organization governance data from seeds or a side door.
  • Build the 12 SEA administrative files last, from a plain seed-to-file path.

Phase 4: deploy to Stadium

  • Release the package with a version number.
  • Give the partner the edfacts_config and xwalk_edfacts_* seeds to fill.
  • Add one Airflow task to the partner DAG. The task runs the edfacts tag and exports each file model to the state drop location.
  • Select the reporting year with one dbt variable.
  • Make sure one partner makes its Active-set files from its own warehouse and EDPass accepts them.

Decisions the owner must make

  • E1: Keep the package private to Stadium, or publish it. Default: private until Phase 2 proves the shape.
  • E2: Select the first partner for validation data. Default: Grand Bend sample ODS only.
  • E3: Select the entry point for non-Ed-Fi data. Default: seeds for SEA answers, earthmover for staff and organization data.

Out of scope

  • Do not run Generate, SQL Server, or CEDS at run time.
  • Do not automate the EDPass submission. EDPass has no public API.
  • Do not make state files that are not EDFacts files.
  • Do not change the Ed-Fi ODS or API.
